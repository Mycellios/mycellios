# Unified speech replica

Status: proposed, not implemented. Long-form jobs that use it are specified in
`specs/long-form-transcription/spec.md`.

## Goal

One speech service per node serves every audio model the network offers
("Ollama for voice"): a catalog of pinned models requested by name, loaded on
demand, unloaded when idle, behind one local API. Kokoro speech and Whisper
transcription become models of this replica instead of separate systems, and
new audio tasks (voice activity, word alignment, speaker labels) are added as
catalog entries, not as new runtimes.

## Current state

- Kokoro: its own adapter (`src/adapters`), engine
  (`python/distributed_runtime/kokoro_engine.py`), environment
  (`python/requirements-kokoro.txt`) and replica.
- Whisper: its own adapter (`src/adapters/transcription.ts`), engine
  (`python/distributed_runtime/transcription_engine.py`) and a hand-deployed
  replica on one contributor (`deploy/transcription-start.ps1`) that reuses the
  Kokoro virtual environment.
- Each has its own admission, qualification and billing wiring.

## What Mycellios keeps from Ollama, and what it does not

Kept: models addressed by name, one local API, load on demand, unload when idle.

Not adopted: an upstream model manager that downloads by name from Hugging Face
(Speaches, LocalAI). Mycellios already owns the safer versions of those jobs:

- Catalog and downloads: content-addressed artifacts pinned by revision and
  SHA-256, distributed as signed node components
  (`specs/node-runtime-auto-update/spec.md`). Nodes never fetch "latest" and
  never need a Hugging Face token.
- Load/unload by demand: the coordinator's native replica placement
  (`specs/on-demand-replica-placement/spec.md`) grants reservations on demand
  and releases idle, unpinned replicas after minimum residency.
- Which node runs what: coordinator scheduling over per-model native
  qualification, which settlement depends on.

## Shape

**Catalog.** A versioned contract under `src/contracts` lists each speech model:
public id, task, engine, artifact digest, supported hardware roles, memory
estimate, input/output bounds and pricing unit. Every entry is pinned and
qualified per digest and hardware role; adding a model is a catalog change plus
its qualification, never a new runtime.

**Tasks.** `vad`, `transcribe`, `align`, `diarize` (segmentation and speaker
embeddings), `synthesize`. Each task has a strict input/output schema bound to
the input hash, like the current `mycellios-transcription/1` envelope.

**Local API.** One loopback-only, credential-free HTTP service per node with
`/health` (loaded models, artifact identities, hardware role) and one endpoint
per task. The existing worker owns admission and leases; the replica owns model
loading. Loading a model requires a committed reservation from the coordinator.

**Engines.**

- Base engine: sherpa-onnx (Apache-2.0). One native library covering VAD,
  Whisper and other ASR families, Kokoro/Piper TTS, speaker segmentation and
  embeddings, on Windows, Linux, macOS and Android, on CPU, CUDA and CoreML.
- Optional engine: `faster-whisper` / CTranslate2 for large Whisper on NVIDIA,
  added only if a side-by-side measurement on the same GPU shows a material
  speed or quality gain over sherpa-onnx for Spanish and English.
- Engines are an implementation detail of a catalog entry; callers see model ids
  and tasks only.

**Environment.** One optional speech environment, separate from the portable
distribution runtime every node installs, with one hashed lock per supported
platform generated by `scripts/generate-portable-runtime-wheel-locks.mjs`. No
media decoders: audio arrives as canonical PCM. Downloaded only by nodes whose
owner enables speech contribution and whose hardware can be qualified.

**Hardware roles.** NVIDIA CUDA: every task, including large transcription.
Apple Silicon (CoreML/CPU) and CPU-only PCs: small models and tasks whose
measured speed meets the deadline. Phones: later, after desktop qualification.
AMD/DirectML: only if the chosen engine build supports it; verify before
advertising.

## Migration

0. Done: `src/contracts/speech-catalog.ts` lists Whisper and Kokoro, and
   `src/adapters/speech-replica.ts` serves both through one adapter class.
   Deployments keep their existing `transcription`/`kokoro` adapter kinds,
   runtime identities and error codes, so live nodes need no change or
   requalification. A single `speech` kind follows with the unified service.
0b. Done: `python/distributed_runtime/speech_service.py` hosts the configured
   models in one process. It serves the unified API on its own loopback port
   (`GET /health` with loaded models, `GET /models/<id>/health`,
   `POST /models/<id>/<task>`), and each model's previous API on its previous
   port, so workers keep their adapter configs. It imports the existing
   source-pinned engines unchanged (`transcription_engine.py` keeps the hash its
   launcher and qualification check). A model whose GPU reservation lapses is
   unloaded and fails closed while the others keep serving. Configured by
   `MYCELLIOS_SPEECH_SERVICE_CONFIG` (`{"port": 8895, "models":
   {"mycellios-whisper-small": {"legacyPort": 8892, "gpuConfig", "artifacts",
   "modelPath"}, "mycellios-kokoro-es": {"legacyPort": 8890}}}`; CUDA Kokoro
   adds `"gpuConfig"` and `"core"`).
0c. Done: `deploy/speech-start.ps1` starts one service process plus each
   model's existing worker, from `speech-launcher.json`. It pins every imported
   source by SHA-256, keeps the transcription private-qualification gate,
   refuses occupied ports, waits for each model's pinned artifact identity,
   discards service stdout (node-owner-privacy D6) and bounds total memory.
0d. Done: lease resilience and CUDA Kokoro, after both per-model replicas on a
   Wi-Fi node restarted thousands of times: one timeline read slower than the
   guard's 3 s timeout killed the process, which then reloaded its model.
   - The pinned `replica_gpu_guard.py` is unchanged. The service gives it a
     fetch with an 8 s timeout and up to three attempts (0.5 s and 1 s
     backoff), still HTTPS-only, without redirects and capped at 1 MiB, and
     passes engines a `LeaseKeeper` in place of the guard. Transport failures
     (timeouts, resets, HTTP 5xx/429) keep serving only inside the last
     confirmed lease: confirmed at most 25 s ago (below the coordinator's
     default 30 s release gap) and expiring more than the guard's 20 s margin
     from now. Owner policy is still checked on every call; any other answer
     (paused or draining owner, closed schedule, invalid identity or expiry,
     missing reservation, HTTP 4xx, redirect) unloads at once.
   - Models load on demand: the process never exits because of a reservation.
     An unloaded model releases its GPU memory (it waits for running requests,
     then collects and empties the CUDA cache), answers 503 with its usual
     error code, and is retried with backoff (5 s doubling to 60 s) until a
     committed reservation is confirmed again. `/health` reports
     `loaded: false` meanwhile.
   - CUDA Kokoro hosts the qualified core `kokoro_cuda_core.py` byte-identically
     (SHA-256 `cb695aae…`, the `gpuCoreSourceSha256` its reservation canary pins)
     with every invariant of the former hand-deployed wrapper: one device with
     the configured name, a 768 MiB allocator limit inside the 2048 MiB
     reservation, fp32 weights with TF32 off, an unbilled startup canary with
     RMS above 50 on every load, a lease check before each synthesis and the
     same API on port 8890 (`/health` with execution evidence, `/metrics`,
     `Server-Timing`, error codes). Its `wrapperSourceSha256` is now the hash of
     `speech_service.py`. Neither the worker, the adapter nor the coordinator
     reads that field: native qualification binds worker, deployment,
     activation, model digest, build source and physical node
     (`src/coordinator/native-qualification-watch.ts`) and the reservation guard
     checks the core hash, so switching needs no new reservation canary.
   - One process has one CUDA allocator: each engine's
     `set_per_process_memory_fraction` call is attributed to the model being
     loaded and the process fraction is the sum of the loaded models' bounded
     shares (Whisper 1536 MiB + Kokoro 768 MiB inside their two 2048 MiB
     reservations). Peak-memory evidence is process-wide.
   - The launcher starts each worker the first time its model reports ready,
     pins worker entries (`entrySha256`), passes `MYCELLIOS_*` worker
     environment (the transcription worker needs its GPU config path) and only
     restarts when a process actually exits.
   - The node's pinned `transcription_engine.py` (`b5b4cc02…`) is the
     repository file with CRLF line endings, so both expose the same
     constructor and evidence; deploy the node's own copy to keep its hash.
   Pending: install and qualify it on a real node (replacing the two per-model
   launchers there), then the `speech` adapter kind for the unified API.
   Physical CUDA checks of this step have not run in CI.

Each step preserves existing public model ids, request contracts, billing
(recognized text tokens for transcription, synthesized text tokens for speech,
never audio bytes), receipts and no-replay rules.

## Qualification

Catalog/schema tests, engine-agnostic task contract tests, lock and
production-UID import tests per platform, signed install with canary and
rollback, and per digest and hardware role: private GPU samples plus normal
native qualification leases. Physical tests that cannot run are reported as
skipped, never as passing.

## Out of scope

Live streaming calls (`specs/realtime-mico-calls`), translation, and public
model uploads.
