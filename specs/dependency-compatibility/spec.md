# Dependency compatibility qualification

Qualify pending dependency proposals against current main without deploying a
runtime or modifying concurrent drafts. Integrate only compatible changes through
the protected PR checks. A passing build is not proof that a native dependency
graph or older supported browser remains compatible.

## Distribution HTTP runtime

Upgrade aiohttp from 3.14.3 to 3.14.4 together with its required yarl 1.25.1.
Keep all other previously locked artifacts unchanged. Generate the Windows x64,
Linux x64 and macOS arm64 CPython 3.12 locks from pip reports under the existing
version constraints and canonical lock generator. Derive the new lock digests
from generated bytes; update policy, runtime probes and their fixtures together.

Install the exact hashed Windows graph in an isolated, checksum-verified copy of
the policy's CPython 3.12.13 artifact. Run dependency consistency checks, affected
Python HTTP/server tests, portable policy/lock tests, accelerator runtime tests
and incremental TypeScript checks locally. The full offline suite is a separate
confirmation; never report Linux/macOS hardware qualification from Windows tests.

## Deferred major proposals

The Expo Router 58 proposal conflicts with SDK 57's bundled Router 57 range and
six existing peer versions, including Expo Constants, Linking and native screens.
Retain it for a coordinated SDK migration instead of forcing peer installation.

Mermaid 12's focused tests pass on the current Node/DOM environment, but its
browser floor is Safari 17.4. The mobile app's Expo baseline still includes iOS
16.4 and receives the untranspiled IIFE directly from the API. Keep Mermaid 11
until the older WebView can be qualified or a browser-floor migration is explicit.
Do not mistake simulated renderer tests for that physical compatibility proof.
