# Invite-only primary account registration

Hosted Agent uses the primary Mycellios account before it creates a local workspace. A closed beta therefore needs two admission checks. The primary identity database refuses new accounts without the invitation. Agent still checks the invitation and admits at most its configured number of new workspaces. An existing primary account can sign in as before. Anyone who has never used Agent still needs its invite and a free place.

## Enrollment and activation

1. The beta link sets the existing Agent-scoped HttpOnly cookie. During email signup the hosted sign-in page requests a short-lived proof from Agent. The proof binds the invitation to the submitted email without returning the invitation code or accepting a browser-supplied proof key.
2. When enabled, the primary identity database validates the proof on every new account insertion. Only the email form can create accounts during the beta. Existing OAuth identities continue using the existing sign-in flow. The quota is charged in the same transaction as insertion and only after validation. Failed inserts release any capacity they held. The proof is removed from primary user metadata and expires within five minutes.
3. Deploy the Agent endpoint and hosted login asset first. Apply `deploy/primary-account-beta.sql` with the identity migration owner and verify `extensions.hmac` is available. The policy is inactive until populated. Store the HMAC key derived as SHA-256 over the UTF-8 string `mycellios:primary-signup:key:v1:` followed by the same invite code. Bind that binary key and the capacity as parameters when inserting the singleton policy row. Keep the key out of logs, artifacts and public database roles. Preserve the policy row and counter across deploys. A key rotation for the same cohort keeps the counter.
4. Before sharing the link, qualify the integrated login and Agent flows against isolated production-equivalent identities. Verify direct email and OAuth account creation without an invitation, a request for another address, and concurrent invitations at the last available place. Verify an existing account can still sign in and a verified invited registrant reaches Agent in the same browser. Check that primary and Agent admission are active in production before opening the forum. To suspend new enrollment without reopening public registrations, keep the identity policy in place and set its capacity equal to the number admitted, or clear the configured Agent invite while retaining the database gate.

The primary and Agent counters bound different resources. An existing primary account can claim an Agent place without consuming a primary account place. Deleting an account does not free an invitation place.
