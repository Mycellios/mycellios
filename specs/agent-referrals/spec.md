# Verified Mycellios referrals

Each verified new account may redeem one first-touch invitation. Both accounts receive 1,000,000 internal promotional microunits (1 Credit), expiring 14 days after redemption. Rewards are not Spore or purchased/earned funds.

The canonical authority issues random invitation codes and HttpOnly first-touch visit receipts. Receipts survive sign-in redirects for 30 days. The first authenticated account visit binds attribution durably before email verification, allowing completion from another browser without its cookie. Clearing cookies before this first login, or registering outside the shared origin without following the invitation, cannot preserve anonymous attribution. Verified OAuth sessions, never client-supplied account identifiers or API keys, redeem them. Eligibility requires the canonical network account's first creation at or after the visit; an older central SSO identity is not by itself a previous Mycellios network account. Existing network accounts, self-referrals, repeated verified email identities, expired receipts and competing referrers cannot receive another award. A single PostgreSQL transaction records the claim and both grants; retrying a lost response is idempotent.

Credit reservations allocate eligible promotions before durable funds. Expiry removes only unspent, unreserved promotional value. Already-admitted work can settle its reserved allowance after expiry without debiting unrelated funds or inventing settlements. Consumed units remain auditable.

Enable only after the separately reviewed schema migration. No production DDL, test accounts or fabricated rewards from UI. Verify real PostgreSQL races, rollback, both awards, partial spending, expiry and pending work; auth/registration redirects, response loss, saved receipt, clipboard and failure UI are focused gates. Delivery requires traced build, rollback, health and native qualification gates.

Migration ownership: apply `expiringPromotionSchemaSql` and `referralSchemaSql` atomically using the existing database migration owner before setting `MYCELLIOS_REFERRALS_ENABLED=true`. Use a private, stable `MYCELLIOS_REFERRAL_EMAIL_PEPPER` of at least 32 characters; rotating it requires a fingerprint migration, not an ordinary configuration edit. The coordinator keeps native schema version 33 and never runs this DDL at startup. Disabling the campaign stops invitations but must keep enforcing expiry on already-issued grants. A rollback to a coordinator predating expiry support requires disabling contribution-funded spending until a compatible wallet is restored; leaving old wallet code live would revive expired promotional value.

Focused verification: through the shared scheduler, run native incremental typechecking, `node scripts/test-referrals-postgres.mjs` with isolated PostgreSQL (CI may install `postgresql libpq-dev` inside its disposable container), `tests/supabase-auth.test.ts`, Agent API/web incremental typechecking and the referral API, InviteFriends, ReferralClaim and MycelliosCredits tests. No production users, balances or physical inference are involved in these fixtures.
